【2026-05-25 — 启动.bat 修复：演示模式 → 完整模式 + 端口自检】
═══════════════════════════════════════════

问题描述：
  用户双击 启动.bat 后浏览器打开的是演示模式（仅巡检+日志分析），
  而非完整Web模式（含知识库问答、巡检、日志分析等全部功能）。

根因分析：
  1. 启动.bat 最后一行为 %PYTHON_EXE% main.py --demo --host 127.0.0.1
     --demo 参数导致 main.py 调用 run_demo_mode() 而非完整 Web 模式
  2. 旧 --demo 进程（PID 31632）未被杀死，长期占用 7860 端口
  3. 用户双击 启动.bat → 新实例端口冲突失败 → 浏览器仍连旧 demo 进程
  4. 没有启动后自检，用户无法判断服务是否成功启动

修复内容：
  ✅ 1. 去掉 --demo 参数
     改前: %PYTHON_EXE% main.py --demo --host 127.0.0.1
     改后: %PYTHON_EXE% main.py --host 127.0.0.1

  ✅ 2. 新增端口清理逻辑（:start_app 前）
     - netstat -ano 检测 7860 端口 LISTENING 状态
     - 自动 taskkill /F 杀掉旧进程
     - 等待 2 秒确认端口释放
     - 若无法终止则提示用户手动操作

  ✅ 3. 新增启动后自检（轮询等待 + 失败提示）
     - 后台启动服务（/MIN 最小化窗口）
     - 轮询 15 次 × 2 秒 = 最多等 30 秒
     - 检测到端口 LISTENING → 显示成功信息 + 打开浏览器
     - 超时未检测到 → 显示失败提示 + 排查指南

  ✅ 4. 添加 setlocal enabledelayedexpansion
     - 支持 for /l 循环内变量动态更新

自检结果（2026-05-25 11:35）：

一、新增 4 个诊断模块
  1. agents/ssl_monitor.py — SSL/TLS 证书监控
     - check_cert_expiry: 单域名证书检测（剩余天数/CN/颁发者/SAN）
     - batch_check_certs: 批量检测 + 自动分级汇总
     - 支持 cryptography 库增强解析，不可用时降级为标准库 ssl
     - 配置: ssl_monitor.domains / ssl_monitor.warn_days

  2. agents/network_diag.py — 网络诊断工具箱
     - ping_host: ICMP 连通性 + 延迟 + 丢包率
     - check_tcp_port: TCP 端口开放检测 + Banner 抓取
     - dns_resolve: DNS 解析（A/AAAA/CNAME/MX）
     - traceroute_host: 路由追踪（tracert/traceroute）
     - http_health_check: HTTP 状态码 + 响应时间 + Header 摘要
     - Windows/Linux 双平台命令适配

  3. agents/db_inspector.py — 数据库健康巡检
     - check_mysql_status: 连接/慢查询/InnoDB缓冲池/主从延迟
     - show_mysql_slow_queries: 慢查询详情
     - check_mssql_status: 版本/连接/阻塞/备份状态（新增）
     - check_oracle_status: 表空间/会话/归档日志（新增）
     - check_redis_status: 内存/命中率/持久化/键统计
     - 通过 mysql/sqlcmd/sqlplus/redis-cli 命令行客户端执行

  4. agents/security_audit.py — 安全基线检查
     - audit_ssh_config: SSH 服务安全配置审查
     - check_failed_logins: 失败登录审计 + 暴力破解检测
     - audit_firewall_rules: iptables/ufw/firewalld/Windows防火墙
     - check_listening_ports: 监听端口审计 + 高危端口告警

问题: 桌面版启动画面在服务 HTTP 就绪（uvicorn 监听）后即载入主界面，
      而知识库引擎（嵌入模型）首次加载需 20~40 秒。用户进入界面后
      首次问答阻塞或报"知识库引擎未就绪"，体验差。

根因:
  1. /api/health 静态返回 {"status":"ok"}，不反映组件就绪情况
  2. get_kb_agent() 首次请求才懒加载 KnowledgeBaseAgent（20~40s）
  3. 懒加载无锁，并发请求会重复初始化（双倍内存/竞争）

修复（3 层配合）:
  1. ui/server.py — KB 就绪状态机 + 启动预热
     · 新增 _kb_state(loading/ready/unavailable) + _kb_lock + 代数计数
     · FastAPI lifespan 启动时后台线程预热（不阻塞 uvicorn）
     · get_kb_agent() 线程安全：并发只初始化一次，初始化中返回 None
     · unavailable 粘性：失败后不随请求重试（避免每次请求阻塞 20~40s），
       仅热切换/重启恢复
     · /api/health 上报 kb_state/kb_error
     · 全部 KB/KG 端点未就绪时返回 {"state":..., "result":友好提示}
     · /api/config/save 热切换重置状态+代数+重新预热（丢弃旧配置实例）
  2. ui/templates/index.html — 就绪轮询 + 加载态
     · 每 2s 轮询 /api/health（原生 fetch 静默，避免 toast 刷屏）
     · 知识问答页工具条状态文本 + 知识库页横幅
     · chatSend/batchAsk 未就绪拦截提示
  3. desktop_app.py — 启动画面等待真实就绪
     · 新增 health_status() 解析 JSON；bootstrap 等待 kb_state∈{ready,unavailable}
     · 启动画面实时显示"正在加载本地嵌入模型… 已等待 N 秒"
     · 8 秒后出现"跳过等待，直接进入"按钮（evaluate_js 轮询 _skipWait）

【2026-08-13 — 方案A：绿色版业务代码外置（免重打包更新）】
═══════════════════════════════════════════

背景: 绿色版 exe 把全部代码冻结在 PYZ 内，每次改代码都要重打包
      （PyInstaller 全量 4~6 分钟）。用户希望像游戏更新一样免重打包。

方案A 设计:
  · exe 同目录 app/ 存放业务代码（main.py + ui/ + agents/ + utils/）
  · desktop_app.py 启动时把 app/ 插到 sys.path 最前，压过 PYZ 冻结副本
  · PYZ 保留冻结副本作兜底：app/ 被误删时自动回退（优雅降级）
  · 更新代码 = 覆盖 app/ 文件 + 重启，秒级生效

关键实现:
  1. desktop_app.py:
     · sys.path.insert(0, BUNDLE_DIR) 之后才插入 EXTERNAL_APP_DIR，
       确保 app/ 位于 sys.path 最前（顺序反了会被 PyiFrozenFinder 命中 PYZ）
     · app/ 缺失时（冻结版）：GUI 显示错误页 / 后端日志明确报错退出
  2. oa_agent.spec: 保持不变（ui/agents/utils 留在 PYZ 做依赖分析+兜底）
  3. scripts/更新绿色版代码.bat: 新脚本，robocopy 源码 → dist\OA运维Agent\app\
  4. scripts/打包绿色版.bat: 增加运行时数据备份/恢复（data/.env/config.yaml），
     打包后自动调用更新脚本
  5. 使用说明.txt: 补回项目根目录（spec datas 引用），更新 app/ 目录说明

踩坑记录（重要）:
  · bat 脚本必须 CRLF + GBK 编码：LF 换行的 GBK 中文 bat 会被 cmd 错位解析
    （注释被当命令执行、路径错乱）
  · cmd //c 在 git-bash 下会退化为交互式 cmd（打包脚本后台运行失败一次）；
    验证 bat 用 python subprocess(["cmd","/c",bat]) 可靠
  · PyInstaller excludes 掉业务包会导致其第三方依赖不被分析
    （fastapi.staticfiles 缺失）→ 放弃 excludes，改用 sys.path 遮蔽方案
  · PyiFrozenFinder 挂载在 _MEIPASS 路径上，sys.path 顺序决定 PYZ/外置优先级

验证（全部通过）:
  · 决定性验证: 仅修改 app/ui/server.py 加 marker → 重启 exe →
    /api/health 返回 marker ✅（未重新打包）
  · 更新脚本还原: marker 消失 ✅
  · 冻结版启动: loading→ready 4.3s ✅
  · 全端点回归 8 项 200 ✅
  · OCR: 冻结版识别"视觉测试/Answer: 42" ✅
  · 绿色版整体流程: 备份→打包→恢复→同步 手动复刻通过
    （打包 bat 本身留待用户双击场景实测）

遗留:

  · 打包 bat 的 cmd 交互路径未在本会话实测（pause/stdin 场景）
