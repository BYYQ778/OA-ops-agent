# 服务器端口与服务访问检查手册

## 概述
本手册规范「端口没监听」「端口监听了但访问不通」两类场景的检查动作，适用于 RHEL/CentOS 7 及以上的 Linux 服务器与 Windows Server 2016 及以上系统。检查顺序要求先本地回环、后外部访问，逐层收敛问题范围。

## 查看监听状态
Linux 使用 ss -lntp 查看 TCP 监听（-l 监听态、-n 数字端口、-t TCP、-p 进程），老系统用 netstat -tulnp 兜底，重点关注 LISTEN 行的绑定地址与进程名。数据库、缓存类服务只监听 127.0.0.1 属于高危配置，应改为监听业务网卡地址并配合防火墙限制来源。Windows 用 netstat -ano 配合任务管理器按 PID 找进程。

## 端口未监听的分层排查
1. 进程层：ps -ef 加 grep 过滤服务关键字，确认进程是否存在、启动参数是否正确；
2. 服务层：systemctl status 服务名，确认 active (running) 与最近日志；
3. 日志层：journalctl -u 服务名 -n 100 --no-pager 查看报错与端口绑定失败信息；
4. 配置层：核对配置文件内绑定地址与端口是否被改错；
5. 冲突层：ss -lntp 查看端口是否被其他进程占用，冲突时先停旧进程再启动新进程。

## 防火墙与 SELinux 影响
服务正常但外部不通时，先查本机防火墙：firewall-cmd --list-all 查看放行列表，缺规则时用 firewall-cmd --add-port=8080/tcp --permanent 放行并 reload。启用 SELinux 的系统还要核对端口标签：getenforce 查看当前模式，semanage port -l 查询允许列表，未授权端口用 semanage port -a -t http_port_t -p tcp 8081 添加，变更记录留存。

## 服务状态与自启
systemctl is-enabled 服务名 确认是否开机自启；未启用时执行 systemctl enable --now 服务名 同时完成设自启与启动。服务反复重启失败时，先用 journalctl -u 服务名 -p err 过滤错误级日志定位。

## 本地回环验证
服务状态正常但客户端连不上时，先在服务器本机执行 curl -v http://127.0.0.1:8080/health：回环可达说明服务本身正常，问题定位到网络路径或防火墙；回环不可达则是应用自身问题，转入应用日志排查，不再纠缠网络配置。

## 访问链路分段验证
跨网段访问不通时按「本机回环、本机业务网卡、同网段邻居、跨网段目标」四段验证，每段记录结论。任一段不通即暂停向下排查，先把该段修通，避免多因素叠加造成误判。

## 常见误区
把「防火墙已放行」当成「服务已监听」，或只看端口号不看绑定地址，都是常见误判；排查时应分别确认监听、放行、路由三段状态，再下结论。修改绑定地址后必须重启服务并重新用 ss 复核。

## 检查清单
- [ ] ss -lntp 输出中目标端口与绑定地址已确认；
- [ ] 本机回环 curl 验证通过；
- [ ] 防火墙规则与云安全组已核对；
- [ ] SELinux 端口标签已确认；
- [ ] 服务自启状态已设置。

## 注意事项
- 严禁用 setenforce 0 长期放宽 SELinux，临时验证后必须恢复 enforcing；
- 端口放行遵循最小化原则，只对必要来源网段开放，并登记放行台账；
- 监听 0.0.0.0 的服务必须确认上层有防火墙或安全组兜底。
- 端口检查结果与台账不符时，先更新台账再调整服务，防止误停在用端口；
- 对第三方系统开放的端口每半年复核一次必要性。

## 附录：常见现象对照表
| 现象 | 常见原因 | 处置入口 |
|---|---|---|
| 连接被拒绝 | 无进程监听或端口写错 | ss -lntp 核对后重启服务 |
| 连接长时间挂起 | 防火墙 DROP | 检查 firewalld 与安全组 |
| 仅本机能访问 | 只绑定了 127.0.0.1 | 修改绑定地址 |
| 服务反复重启 | 端口冲突或配置错误 | journalctl 查看报错 |
| 间歇性失败 | 连接数打满 | 检查 ulimit 与 backlog |
