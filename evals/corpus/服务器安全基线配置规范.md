# 服务器安全基线配置规范

## 概述
本规范规定 Linux 生产服务器上线前必须完成的安全加固项，覆盖账号口令、远程登录、提权管理、日志审计、补丁与端口收敛六个方面，适用于 RHEL/CentOS 7 及以上系统。新机器交付前由系统管理员逐项自检，安全组按月抽查并通报偏差。

## 账号与口令策略
- 口令长度不少于 12 位，须包含大小写字母、数字与符号中的三类；
- /etc/login.defs 中设置 PASS_MAX_DAYS 90、PASS_MIN_LEN 12；
- 通过 pam_pwquality 启用复杂度校验，连续 5 次认证失败锁定账号 10 分钟；
- 人员离职当天禁用账号（usermod -L），一周后确认无关联业务再删除；
- 禁止共享账号，一人一号一密钥。

## SSH 加固要求
/etc/ssh/sshd_config 至少完成以下调整：Port 改为 22022；PermitRootLogin no；PasswordAuthentication no 且仅保留密钥认证；MaxAuthTries 3；LoginGraceTime 30；通过 AllowGroups 限制可登录用户组。修改后务必先执行 sshd -t 检查语法，再重启 sshd 服务，避免把自己关在门外。

## sudo 与提权管理
- 普通运维账号需提权的一律走 sudo，禁止直接登录 root；
- 授权文件统一放在 /etc/sudoers.d/ 下按人拆分，使用 visudo -f 编辑；
- 只授予完成工作所需的最小命令集，禁止 NOPASSWD: ALL；
- 每季度复核一次 sudo 权限清单，清理离岗人员授权。

## 日志与审计
- auditd 保持运行，对 /etc、/bin、/usr/sbin 等关键目录配置写入类与属性类审计规则；
- 远程登录、提权、账号变更日志集中转发至日志服务器 10.20.30.20；
- 服务器本地日志保留不少于 180 天；
- 每月抽查一次审计记录完整性，发现缺口及时上报。

## 补丁管理
- 安全补丁每月第一个周六 22:00 至次日 00:00 窗口实施；
- 先在 2 台非核心机器灰度验证 3 天，再全量推送；
- 内核升级必须安排重启窗口，重启前确认业务切换完成；
- 每次补丁后归档更新记录与灰度机验证结论。

## 禁用不必要的服务与端口
telnet、ftp、rsh 等明文协议一律停用（systemctl disable --now）；默认不开放的端口不监听；已确需保留的端口登记用途与责任人。整改结果用 ss -lntp 复核。

## 等保检查点清单
| 检查项 | 要求 |
|---|---|
| 口令复杂度 | 12 位混合字符，90 天更换 |
| 远程登录 | 密钥认证，禁 root 直登 |
| 提权控制 | sudo 最小授权，季度复核 |
| 日志审计 | auditd 运行，保留 180 天 |
| 补丁状态 | 月度窗口，灰度后全量 |
| 端口收敛 | 无用服务停用并登记 |
| 账号清理 | 离岗当天禁用账号 |

## 基线核查方式
上线前由系统管理员对照本规范逐项核查并在检查表上签字；安全组每季度组织一次工具化扫描复检，重点核对 SSH 配置、sudo 授权与开放端口三项，偏差项登记整改责任人与完成期限，复检结果全组通报。

## 高频偏差项
历年抽查中反复出现的偏差包括：临时调试期放宽的口令策略未恢复、离职人员 sudo 授权未清理、旧版本系统未按窗口打补丁、调试用端口长期放行。以上四类在每次复检时优先核对。

## 注意事项
- 调整 SSH 配置前必须保留一个已登录会话，确认新配置生效后再退出；
- 基线整改属于变更，按变更流程提交窗口后实施；
- 抽查发现的偏差项 5 个工作日内完成整改并回执。
- 加固脚本执行前先在非生产机器验证，避免批量误伤；
- 基线核查记录保存至机器下线；
- 供应商维护账号按项目单独开通，项目结束后 3 个工作日内回收。
