# 网络连通性故障排查手册

## 概述
本手册用于快速定位服务器之间互访不通、时通时断、丢包与延迟异常等问题，覆盖同机房内网、跨机房专线、办公网到生产区三类场景。值班工程师按「先通后查、自底向上」的原则执行，每一步操作与结论必须记录到工单，禁止只凭印象口头交接。

## 适用场景
- 业务侧反馈 OA 页面打不开，但应用进程自身运行正常；
- 两台内网服务器 ping 不通，或只有部分端口不通；
- 数据库主从同步延迟升高，怀疑底层链路质量；
- 跨机房互访出现间歇性超时，丢包率随时间波动。

## 排查工具与判读
### ping
ping -c 4 10.20.32.8 先确认基础可达性。100% 丢包时先检查链路、路由，再看对端是否禁 ping，不能仅凭 ICMP 超时就判定主机故障；存在部分丢包时用 ping -c 100 -i 0.2 加大样本，观察丢包率是否稳定。

### telnet 与 nc
端口级验证用 telnet 10.20.32.8 3306 或 nc -vz -w 3 10.20.32.8 3306：返回 succeeded 说明 TCP 三次握手完成；命令长时间挂起多为防火墙 DROP；立即返回 Connection refused 说明路由可达但目标端口没有进程监听。

### traceroute 与 mtr
traceroute -n 10.20.32.8 观察路径在哪一跳中断；mtr -r -c 100 10.20.32.8 可同时看每跳丢包率。中间跳出现的星号不一定是故障，链路质量以目标地址那一跳的丢包率为准。

## 丢包与延迟定位
主机侧先执行 ip -s link show eth0 查看 errors 与 dropped 计数，再用 ethtool -S eth0 判断丢弃发生在接收侧还是发送侧。若本机计数干净、且 mtr 显示丢包稳定出现在同一跳，转网络组检查该段链路与交换机端口；若同一时刻对端访问本机也异常，优先怀疑网卡协商速率或双工模式，可用 ethtool eth0 核对 Speed 与 Duplex。需要留档时用 mtr -rwzbc 100 10.20.32.8 输出报告。

## 防火墙放行检查
排查前先确认两端防火墙状态：firewall-cmd --state 或 iptables -L -n --line-numbers。RHEL 7 及以上系统执行 firewall-cmd --add-port=8080/tcp --permanent 后接 firewall-cmd --reload 放行端口；低版本系统用 iptables -I INPUT -p tcp --dport 8080 -j ACCEPT 临时放行，并同步将规则写回配置文件。云主机还需核对安全组入方向规则，专线场景核对专线 ACL。

## 内网互访排查流程
按以下顺序执行并逐项留痕：
1. 链路与网卡：ip link 查看 UP 状态，ethtool 查看协商速率；
2. 地址与路由：ip addr、ip route get 10.20.32.8，确认网关正确；
3. 基础可达：ping 目标地址，记录丢包率；
4. 端口可达：nc 或 telnet 目标端口；
5. 应用层：curl -v 访问业务接口，确认服务本身正常；
6. 抓包取证：tcpdump -i eth0 host 10.20.32.8 and port 3306 -nn -c 100，查看 SYN 与 SYN-ACK 是否成对。

## 检查清单
- [ ] 两端 ping 结果与丢包率已记录；
- [ ] 路由表、网关、VLAN 归属已确认；
- [ ] 两端主机防火墙规则已对照；
- [ ] 云安全组或专线 ACL 已核对；
- [ ] 应用进程监听状态已确认（ss -lntp）。

## 注意事项
- 生产环境禁止直接执行 iptables -F 清空规则；确需调整时先执行 iptables-save 备份到 /root/iptables.bak，并在 10 分钟内保持回滚通道可用。
- 抓包会占用带宽并产生大文件，单次抓取不超过 100 个包，用 -c 参数限流，完成后立即删除临时文件。
- 间歇性问题要约定观察窗口（建议 30 分钟），避免用小样本快速下结论。
- 排障期间的重启网卡、调整路由、放行规则等操作均属变更，须先报备、事后补单；
- 涉及核心链路时，抓包与探测避开业务高峰，优先在镜像端口上操作；
- 排查结论要可复现：记录时间点、源与目标、端口及当时的防火墙状态。

## 附录：常用命令速查
| 目的 | 命令 | 判读要点 |
|---|---|---|
| 基础可达 | ping -c 4 10.20.32.8 | 看丢包率与平均延迟 |
| 端口可达 | nc -vz -w 3 10.20.32.8 3306 | succeeded 即 TCP 可达 |
| 路径追踪 | traceroute -n 10.20.32.8 | 定位中断跳 |
| 连续质量 | mtr -r -c 100 10.20.32.8 | 以目标跳数据为准 |
| 规则查看 | firewall-cmd --list-all | 看 ports 与 rich rule |
| 抓包 | tcpdump -i eth0 port 3306 -nn | 看握手是否成对 |
